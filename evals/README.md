# 模型质量评测材料

当前状态：输入已准备，**真实模型运行 0 次，人工质量评分未开展**。不能将离线适配器测试当作生成质量通过。

`regular.json` 是 20 个虚构消费品案例，R01–R12 为开发集，R13–R20 为保留集，各做两轮四步骤（方案、小红书、抖音、复盘），共 40 个工作流包、基础 160 次调用。`abnormal.json` 包含 10 个异常场景。`manifest.json` 固定输入摘要；开始评测后不要再重新生成输入。

这些场景用于检查事实忠实度和工作流适配，不是统计上代表所有营销品类的基准。保留集未被用作本次调参；如以后用于修复提示，需替换保留集。

## 准备与执行

```bash
npm run eval:prepare
```

真实运行通过当前 shell 安全配置 `OPENAI_API_KEY`、`AI_MODEL`。不要把密钥写入命令历史或提交文件。CLI 不自动加载 `.env.local`。

| 变量 | 含义 |
| --- | --- |
| EVAL_LIVE_CONFIRM | 显式设为 `I_UNDERSTAND_COST` 才运行 |
| EVAL_SPLIT | `development` 或 `holdout`，默认前者 |
| EVAL_MAX_CALLS | 尝试次数上限，默认 12；开发集两轮至少 96，保留集至少 64，重试另计 |

```bash
npm run eval:run
```

输出逐例保存于 `artifacts/evals/<时间>/`，含模型名、原始响应、耗时、token、错误及尝试数。它是独立离线评测，不写生产数据库、不发布内容、不伪造人工批准。达到上限的失败样本保留。配额上限不是美元花费保证；应在供应商侧另设预算，先用少量开发样例核算费用。

异常场景涉及输入、模型和基础设施不同层：A05–A10 的确定性部分由单元/集成测试覆盖；A01–A04 仍需模型实测与人工阅读，尤其提示注入的语义抗性不能从 mock 推断。

## 人工评分

每个工作流包检查 5 维：事实忠实度、渠道适配、可执行性、分析依据、表达清晰度。每维 1–5 分，另记硬事实错误数、引用不支持、编造效果、遗漏限制、评审者和修改建议。

目标：硬事实错误 0；总体均分≥4；各维≥3.5。目标不是本次结果。不能为凑达标删除失败样本。评测者若只有开发者须标明自检，不能称独立评审。

手工填分前先逐项核对：价格/颜色/数量是否有资料，来源是否被错误复述；脚本实际试读是否合适；数值是否来自代码；是否把归因订单说成首购或把 ROAS 说成净利润；是否把观察写成因果。
