# AI 营销活动工作台 从 0 到 1 实施规划

这套规划用于准备“AI 营销解决方案专员”面试作品。目标是做出一个可提交 GitHub 链接、可在线体验、也能解释业务价值和实现方法的个人项目。

建议作品名：**营策台 CampaignPilot**。它将产品资料与活动需求转成可审核的营销内容，再通过 CSV 数据回传支持复盘和下一轮测试。

**当前状态：已完成规划文档。软件、远程 GitHub 仓库、在线 demo、测试结果和录屏均尚未交付。** 本轮没有开始软件开发，文档中的验收结果都是待执行标准。

## 作品将完成的流程

    品牌事实与活动需求
             ↓
    AI 活动方案与三个内容角度
             ↓
    小红书图文文案 + 抖音 30 秒文本脚本
             ↓
    人工编辑、事实检查、版本审核、文件导出
             ↓
       人工在外部平台执行
             ↓
    CSV 回传 → 代码计算指标 → AI 解释与复盘
             ↓
    人工选择下一轮实验建议

主案例是虚构品牌“轻行”的通勤背包：18L、0.65kg、独立电脑隔层、标价 299 元、活动价 269 元，14 天预算 5,000 元，目标是获取可归因订单。产品事实、预生成内容和投放数据均为样例。

这个范围可以展示需求拆解、营销方案、AI 接入、流程自动化、质量控制、数据分析和工程交付。首版只交付文本，不包含自动发布、真实广告投放、图片或视频生成。

## 两种模式

| 模式 | 适合谁 | 能力 | 明确边界 |
| --- | --- | --- | --- |
| 公开演示 | 面试官与访客 | 无注册、无密钥体验样例；本地编辑、审核、导出和指标计算 | AI 结果预生成；改了关键输入后不伪装成新的生成 |
| 受保护真实模式 | 项目负责人或获授权评审 | 使用自己的资料调用模型，保存版本、审核、导出和分析 | 需要账号和服务端配置；真实调用受费用与次数限制 |

GitHub 评审应能够无密钥运行演示模式；真实 AI 是否可用及如何配置在实现后的 README 中如实说明。接口不可用时不能把预生成结果偷偷替代成“真实生成成功”。

## 软件做好后必须拿得出的证据

1. **可用性**：一条完整流程录像、公开链接、干净环境复现记录。
2. **工程正确性**：权限、事务、幂等、导入、审核版本和故障恢复测试。
3. **数字正确性**：黄金 CSV 的合计 CTR 为 2.3333…%、CPA 为 70 元、ROAS 为 3.842857…，由代码计算且可手算核对。
4. **AI 内容质量**：20 个常规案例各两轮的完整输出包、10 个异常案例、人工评分及失败样本。
5. **真实贡献**：本人做出的需求取舍、代码判断、验证和交付工作，以及 AI 辅助的具体环节。

没有真实投放，不写转化提升；没有前后测，不写效率提升百分比；没有实际执行测试，不写测试通过。

## 常用术语

| 术语 | 在本项目中的含义 |
| --- | --- |
| MVP | 保留核心闭环的第一版可用软件 |
| brief | 活动需求表，明确目标、人群、时间、预算和限制 |
| fixture | 固定样例输入和预生成结果，供无密钥演示与测试 |
| Schema | 输入或输出必须遵守的字段与类型规则 |
| RLS | 数据库按用户身份限制可读写的记录 |
| 幂等 | 同一个业务请求重复发送，不重复保存结果或累计数据 |
| E2E | 从用户操作起点走到最终结果的完整流程验证 |
| variant | 一条可与表现数据对应的内容变体，例如 A/B 文案 |
| 快照 | 某个时间点的不可变输入或结果，供历史追溯 |
| ROAS | 归因销售额除以广告花费，不等于净利润率 |
