## 测试究竟证明了什么

领域测试覆盖必填和日期、重复事实 ID、预算、引用、禁用表述、版本过期、改稿撤销批准、交付锁定、新变体、CSV 公式防护、金额、黄金指标、零分母、CSV 行错误、文件/自然键重复、大小与行数上限、警告确认、报告过期、样例输入匹配、A/B 交换数据不得冒用样例复盘、独立下一轮活动与损坏存储恢复。

模型适配器使用可控响应替身：结构错误、拒绝、不完整响应、连接未知、rate-limit 一次重试、余额不足不重试、Retry-After 超预算、usage 缺失保留未知；验证资料与指令分层且没有工具执行通道。**不证明真实模型不会幻觉或一定抵御语义注入。**

Postgres 集成使用 PGlite 的实际 PostgreSQL 引擎，执行完整 migration、A/B RLS、匿名拒绝、直接写与 RPC 权限、CAS、历史、幂等、次数/费用预留、尝试上限、原子结果提交与旧输入结果拒绝。它不是完整 Supabase 网络服务，不覆盖托管认证、真实 JWT、多连接高负载或供应商故障。

浏览器测试使用静态生产包，覆盖：访客存储隔离与重置；编辑阻断与重审；实际下载；黄金导入与复盘；重复/错币种；修改输入后的样例限制；390px 无横向溢出；来源与分镜；确认后创建新活动；未保存离开、存储损坏恢复；弹窗 Tab 焦点与 Escape 返回。

## 缺陷与修复记录

1. 浏览器测试对多个相同数字使用单元素定位，出现严格定位失败；改成明确限定目标。不是隐藏产品失败。
2. 在运行浏览器测试时更新开发源/重建同一静态目录，曾出现页面重载或短暂无内容；改为固定生产包和顺序构建，最终完整 10 项通过。
3. 新活动字段测试误用了“活动标题”而真实标签是“活动名称”，改成正确可访问名称。
4. 样例复盘最初只比总数，A/B 交换仍可能复用旧解释；改成逐变体匹配并增加反例。
5. 成功生成使 revision 增加后，同键重发先被版本冲突拦截；改为先核对既有幂等结果，并以 API 回归测试验证。
6. 下一轮建议最初改写当前 brief；改为确认后创建新活动，保留原始内容与数据。
7. 本地存储原先只检少量字段；改为完整结构校验，异常恢复有提示。新增未保存离开与焦点管理。
8. PGlite 曾在前期环境运行中初始化超时；在指定 Node 24 下重新验证，最终 54 项通过。没有将此前失败记录当成已通过结果。
