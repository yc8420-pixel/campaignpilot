# 实现决策与规划差异

版本：1.0.0，日期：2026-10-28。本文说明实际代码，原始规划不作已验收证明。

## 1. 保留的产品范围

F01–F10 的主线仍为：事实与需求 → 方案 → 两渠道内容 → 人工审核 → 版本锁定导出 → CSV 回传 → 指标与复盘 → 新一轮需求。没有增加自动投放、自动发布、图片/视频生成或多组织权限。

公开 demo 的业务操作是真实执行的浏览器逻辑；AI 内容和复盘是固定样例。真实模式采用同一 UI 与同一领域规则，经服务端认证后访问数据库和模型。静态站不提供真实模式 API。

## 2. ADR-001：共享 UI，两个运行入口

完整应用使用 Next.js；公开演示使用 Vite 构建相同 React 组件。原因是面试官不应被数据库、密钥、服务冷启动或模型配额阻挡。Vite 入口只编入 UI 和领域模块，不能导入服务端凭据。

UI 采用自有 CSS 与 Lucide 图标，替代规划中的 Tailwind/shadcn，减少模板样式与依赖迁移成本。图形是项目内 SVG，不依赖外部图片。界面以暖灰、深绿、清晰事实标签与审核侧栏区分工作阶段。

代价：存在两套构建；因此 CI 同时构建 Next.js 与 Vite，浏览器测试针对静态生产产物。录屏与浏览器测试期间不并行重建同一 dist 目录。

## 3. ADR-002：活动聚合与不可变快照

初版设计列出多张品牌、brief、内容和导入表。实现收敛为 4 张业务表：

| 表 | 内容 |
| --- | --- |
| workspaces | owner_id、revision、活动 JSONB 聚合、更新时间 |
| workspace_revisions | 每次变更后的完整不可变聚合快照，唯一 `(workspace_id, revision)` |
| ai_runs | 幂等键、请求摘要、模型、状态、尝试数、预算、usage、deadline |
| daily_usage | 按用户与 UTC 日期锁定的次数和费用账本 |

来源、内容版本、交付 manifest、导入批次、复盘快照嵌在聚合内。每次业务动作先通过 Zod 与领域规则，再由 `cp_save_workspace` 锁定记录、比较 revision、一次性保存新聚合与历史。并发修改旧 revision 得到 409，不静默覆盖。

这是个人作品与小数据量的取舍，**不宣称已实现每个 JSON 子字段的数据库外键/自然键约束**。CSV 自然键唯一性由领域验证 + CAS 原子提交保证；普通认证客户端无直接写表和调用写 RPC 的权限，唯一写入口为已鉴权服务端。特权服务端若被错误修改，数据库不能替它检查所有业务字段。

扩容时应把内容、导入行和快照拆表，并在数据库增加自然键唯一约束和独立索引；当前每活动最多 20 个变体、累计 50,000 行，单次 5,000 行/2 MB。历史聚合会增加存储开销，不适合长期大规模流水。

## 4. ADR-003：认证、RLS 与服务端边界

登录仅用于预创建 Supabase 账号，不开放注册。访问令牌保存在 HttpOnly、SameSite=Strict Cookie，HTTPS 下加 Secure，最多一小时；当前没有自动刷新令牌，过期后重新登录。每个 API 调用重新验证令牌，私有响应均 `private, no-store`。

RLS 限制认证客户端只能读自己的行；匿名无访问权。服务端 secret key 会绕过 RLS，因此代码必须显式过滤 owner_id、校验资源归属。每个 RPC 的 p_user 来自服务器认证结果，不来自请求体。POST 同时校验 Origin。

测试验证了 Postgres RLS 与服务端权限边界，但未把托管 Supabase Auth 登录、真实 JWT 生命周期及多设备会话称为已联调。

## 5. ADR-004：可控的同步生成

生成分四步：strategy / xiaohongshu / douyin / analysis。每步是同步请求，不提供后台队列。配置 `AI_MODEL`，没有未经测评的默认模型名称。

使用 OpenAI Responses 严格结构输出、`store:false`、SDK `maxRetries:0`，无工具调用。资料作为输入数据；服务端权限、数据库操作不交给模型。Schema 仅检查结构，事实引用存在性和部分禁用/价格规则由领域代码补充；语义是否支持、口播是否自然仍需人工。

每步最多两次尝试，单次 20 秒，总预算 45 秒；仅可重试的 rate-limit 429 重试一次，尊重 Retry-After，余额不足不重试。超时/断连记 unknown，不假装未计费。数据库预留两次调用额度与估计费用；未知 usage 或费用保留预算。

同键同参回放返回既有 run；同键异参返回 409。完成结果与成功状态同事务提交；生成期间输入变化不会覆盖新数据。输出即使生成成功也只是草稿，不能绕过人工审核直接导出。

使用方式依据 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)；本次只做适配器与合同测试，没有真实模型质量结论。

## 6. 版本与数据语义

- 编辑内容产生新 ContentVersion；审核绑定具体 versionId 和输入 revision；审核不是“AI 自批”。
- 首次导出锁定 deliveredVersionId。重新改稿复制新 variant，旧导入数据仍指向旧交付内容。
- 固定样例复盘同时校验品牌/brief、逐变体指标及对应样例文案；相同总数但 A/B 对调也不能冒用旧结论。
- 复盘保留 metric hash 与数字快照；后续新增数据使旧报告显示过期。
- “采用建议”先预览确认，再创建独立活动，保留上一轮原始证据。日期和预算沿用后由人核对。
- 示例事实编号以代码为准：F001 容量、F002 重量、F003 标价、F004 活动价、F005 隔层。早期文档若编号不同，语义不变，不能混用 ID。

## 7. 已知边界与后续重点

真实云端联调、40 份真实输出包、人工评分、5 组效率对比和评审网络访问均未完成。公开 demo 可验收的是固定案例与业务机制，不是对任意营销资料都已证明可靠的 AI 产品。

当前只提供渠道/日期筛选及逐变体表格；独立变体筛选在首版省略。没有数据批次撤销、增量更正、多人协作、历史版本回滚按钮或自动刷新登录。品牌事实冲突由人确认，不自动仲裁来源真假。所有业务范围与实际验证状态在任务台账逐项列出。
