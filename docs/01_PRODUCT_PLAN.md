# AI 营销活动工作台 产品与实施规划

版本：1.0。规划日期：2026 年 10 月 27 日。状态：规划已编写，软件尚未实现，本文中的性能、质量和效率数字均为待验证目标。

## 1 项目定位与最终交付

项目目录名是“AI营销解决方案专员_用 AI搭建的自动化工具或小程序”。据此，把作品定位为面向营销运营的 AI 营销活动工作台，暂定产品名“营策台”，英文展示名 CampaignPilot。命名是工作名称，不表示已经注册品牌或核验商标。

一句话介绍：把产品资料变成有依据、可审核、可导出的营销内容，再把回传数据变成可追溯的复盘和下一轮测试建议。

主要使用者是小型消费品牌的营销运营，一人同时承担活动策划、内容生产和效果汇总。面试官可以通过公开演示体验完整路径，通过 GitHub 检查实现、测试与文档，通过受保护的真实模式观察模型调用。

最终应交付：

1. 可公开访问的中文 Web demo，访客无需注册或提供 API key 即可体验样例。
2. 一个可供评审阅读和复现的 GitHub 仓库，含源码、安装步骤、样例、测试、架构和限制说明。
3. 受保护的真实 AI 模式，支持自己的活动和资料，输出可保存、审核、导出。
4. 三分钟演示视频，以及接口暂不可用时仍可播放的备用录屏。
5. 一组可核查证据：测试报告、人工内容评分、调用成本与时延记录、工作流耗时测量。

本轮交付的是上述软件的实施依据，不包含已经部署的应用、已经创建的远程仓库或已经通过的测试。

## 2 当前假设与设计取舍

用户暂无岗位 JD、目标行业和面试日期，因此使用以下基线，不再以等待这些信息作为推进条件。

| 项目 | 基线决策 | 对实现的影响 |
| --- | --- | --- |
| 使用场景 | 中文消费品营销运营 | 文案、示例、表单和说明以中文为主 |
| 作品形式 | 浏览器 Web 应用 | 点击链接即可试用，适合远程面试 |
| 开发方式 | 一人负责业务判断，AI 辅助实现与排查 | 保留可解释的简单架构与开发记录 |
| 主案例 | 虚构品牌轻行的通勤背包活动 | 所有样例资料可放入公开仓库 |
| 核心渠道 | 小红书图文文案、抖音 30 秒视频脚本 | 只生成文本，不生成图片或视频 |
| 发布方式 | 人工审核后下载文件 | 不依赖真实平台账号授权 |
| 数据来源 | 固定模板 CSV 回传 | 先固定数据口径，再考虑平台连接 |
| 账号 | 真实模式仅预创建账号；不开放注册 | 减少无关账号产品功能与滥用成本 |
| 演示 | 本地样例状态，与真实数据隔离 | 不同访客不会互相修改记录 |
| 默认排期 | 100 小时基础工作量，加 0–25 小时缓冲 | 每天有效投入 5 小时，约 20–25 个工作日 |

排期是工作量估计，受开发熟悉程度、接口可用性和部署条件影响。不得把它解释为已经承诺的交付日期。

## 3 为什么这个作品适合面试

招聘作品需要证明“能把业务问题变成可交付的软件”。本项目将能力落实到可观察的操作和产物。

| 岗位能力 | 软件中体现的位置 | 面试官能验证的证据 |
| --- | --- | --- |
| 需求拆解 | 结构化活动 brief | 目标、人群、预算、渠道、约束均有字段 |
| 营销策划 | 活动方案与内容角度 | 每条建议有目标、受众及验证办法 |
| AI 应用 | 结构化生成和事实引用 | 输出字段、输入版本、模型记录可检查 |
| 流程自动化 | 从方案到草稿、审核、导出的衔接 | 不用反复在聊天框复制上下文 |
| 质量控制 | 事实、禁用表述、版本审核 | 一条无依据表述如何被发现和处理 |
| 数据分析 | CSV 检查、确定性计算、复盘 | 能复算 CTR、CPA、ROAS 等指标 |
| 工程交付 | 异常处理、权限、测试、部署 | 仓库可启动，错误有处理，演示可恢复 |
| 沟通表达 | 三分钟业务演示与技术说明 | 能解释选择、限制和下一步 |

自动化边界是策划、内容准备、审核衔接与复盘辅助。发布、投放和预算调整仍由人操作。只有接入真实平台并验证后，才可宣称真实投放自动化。

## 4 主案例及样例资料

### 4.1 品牌事实

品牌“轻行”和产品资料均为虚构示例。界面、导出物、README 和录屏应标明“虚构品牌／模拟数据”。

| 事实编号 | 已确认的样例事实 | 不允许据此推断的内容 |
| --- | --- | --- |
| F001 | 品牌名轻行，产品为通勤背包 | 真实公司、真实客户案例 |
| F002 | 容量 18L | 可容纳任意尺寸电脑 |
| F003 | 包体重量 0.65kg | 市场最轻、长期背负无压力 |
| F004 | 标价 299 元，活动价 269 元 | 历史最低价、全网最低价 |
| F005 | 有独立电脑隔层 | 防震认证、防摔等级 |
| F006 | 目标用户为城市通勤人群 | 已有某年龄段真实购买占比 |
| F007 | 素材语气为简洁、实用、不过度承诺 | 官方认证、专家背书、用户好评 |

没有提供防水等级、销量、评价、限量库存、保修或认证时，模型不得自行补充。需要这类信息时输出“待确认”，并列出需要补充的字段。

### 4.2 活动 brief

示例为 14 天新品活动，总预算 5,000 元，主要目标为获取可归因订单；目标值由用户设置，默认不自动承诺订单量。日期由样例选择器填入，真实模式须明确开始、结束日期与业务时区。

必填：活动名称、产品版本、业务目标、目标人群、时间范围、预算、主币种、渠道。可选：目标 KPI、已有基准、优惠条件、品牌语气、禁用表述、人工补充说明。

预算分配是建议和约束检查，不是自动投放。若没有足够依据，给出待验证假设；所有分配之和不得超过输入预算。

### 4.3 预期产物

一份活动方案，包含目标、受众假设、三个内容角度、渠道分工、14 天工作节奏、预算建议和待确认事项。用户选一个角度后，生成两个渠道各两套 A/B 内容，方便展示同一卖点的不同表达。

小红书卡片包括标题、正文、话题建议、行动引导、事实引用。抖音卡片包括开场、分镜、口播、画面说明、结尾引导及时间分配，总时长以 30 秒为模板目标。长度和时长是本产品可配置约束，不宣称平台现行官方限制。

## 5 用户主流程

资料录入 → 事实确认 → 活动 brief → 生成方案 → 选择角度 → 生成内容 → 编辑和审核 → 导出 → 平台外执行 → 导入结果 → 指标复算 → AI 复盘 → 人工选择下一轮实验。

平台外执行是业务流程中的人工环节，应用不显示虚假的“发布成功”。导出状态只能说明文件已成功产生。

| 步骤 | 用户操作 | 软件处理 | 可见结果及异常 |
| --- | --- | --- | --- |
| 1 | 打开示例或创建品牌 | 初始化样例，或建立个人记录 | 显示模式、数据来源、下一步 |
| 2 | 填写事实或粘贴资料 | 保存原文和事实条目，检查必填 | 缺失事实可定位；不自动认定 AI 提取内容为真 |
| 3 | 填活动需求 | 检查预算、日期和渠道 | 缺项在字段旁提示，不丢失已填内容 |
| 4 | 点击生成方案 | 冻结输入版本，调用生成服务，校验输出 | 可查看方案、依据、假设、待补信息 |
| 5 | 选择角度和渠道 | 逐步生成渠道内容，保存每步结果 | 前一步成功、后一步失败时可单独恢复 |
| 6 | 修改草稿并送审 | 新建版本，执行规则校验 | 错误项、警告项、审核意见分别可见 |
| 7 | 通过审核并导出 | 校验审核仍对应当前版本 | 获得含内容编号的 Markdown/CSV 文件 |
| 8 | 上传数据模板 | 先解析和预览，再事务提交 | 错误行列可下载查看，整批失败不半导入 |
| 9 | 查看表现 | 用代码计算指标，展示缺失与口径 | 指标可展开看到公式和原始数值 |
| 10 | 生成复盘 | 把已计算指标和内容版本交给模型 | 分开显示观察、解释假设、下一步实验 |
| 11 | 采用一条实验建议 | 预填下一轮 brief，等待用户保存 | 不自动更改广告账户或既有活动 |

## 6 功能范围及验收要点

优先级定义：P0 为正式面试版必须交付；P1 为核心稳定后的增强；P2 为未来版本。若触发压缩方案，必须更新范围和展示措辞。

| 编号 | 优先级 | 功能 | 关键输入输出 | 验收要点 |
| --- | --- | --- | --- | --- |
| F01 | P0 | 演示入口和模式标识 | 一键载入轻行案例 | 无账号无密钥完成样例主流程，清楚标为预生成 |
| F02 | P0 | 品牌事实库 | 手工事实、粘贴原文、语气约束 | 保存、修改、来源引用和输入版本均可追溯 |
| F03 | P0 | 活动 brief | 人群、目标、预算、日期和渠道 | 必填、日期、金额校验，刷新后真实模式不丢数据 |
| F04 | P0 | AI 活动方案 | 已确认事实与 brief → 结构化方案 | 三个角度、预算约束、事实与假设分开 |
| F05 | P0 | 两渠道内容 | 已选角度 → 每渠道 A/B 两版本 | 可编辑，引用可点击，局部失败可恢复 |
| F06 | P0 | 规则和人工审核 | 当前内容版本 → 通过或退回 | 修改后旧审批自动失效；阻断项不能跳过 |
| F07 | P0 | 内容导出 | 已审核版本 → Markdown 和 CSV | UTF-8 可读、内容编号稳定、无待审核版混入 |
| F08 | P0 | 数据导入与指标 | 标准 CSV → 校验结果、指标卡片 | 去重、冲突、零分母、聚合公式正确 |
| F09 | P0 | AI 复盘 | 冻结指标 → 观察、假设、建议 | 引用指标；不制造因果或虚构提升数字 |
| F10 | P0 | 真实模式和工程保障 | 账号、运行记录、预算限制 | 权限隔离、失败处理、密钥保护和调用追踪 |
| F11 | P1 | 结果比较与效率面板 | 人工评分、耗时记录 | 只展示真实测量，说明样本数 |
| F12 | P1 | 更多资料处理 | 文档提取、检索、来源片段 | 确有超长资料需求后再设计 |
| F13 | P1 | 内容日历与排期增强 | 已审核内容、计划日期 | 排期不伪装为平台发布成功 |
| F14 | P2 | 平台接口、图片视频生成 | 经过授权的平台和模型 | 单独评估权限、费用和可用性 |

P0 的审核由同一账号执行，体现流程和版本约束；不实现团队审批、角色矩阵或组织管理。事实库先采用少量结构化资料，无须为了展示概念引入向量检索。

首版排除：爬取竞品网页、社媒自动发布、自动发送私信或邮件、支付订阅、CRM、线索爬取、图片生成、视频渲染、移动端小程序、复杂 Agent 自主操作。每项扩展都应对应新需求和独立验收。

## 7 页面和交互设计

采用左侧导航与右侧工作区，桌面优先，移动端能浏览和完成基本操作。配色以中性底色、单一强调色和清晰状态标签为主。状态同时使用文字与颜色。

| 页面 | 主要区域 | 关键操作 | 必须考虑的状态 |
| --- | --- | --- | --- |
| 欢迎页 | 产品用途、案例预览、演示与登录入口 | 开始演示、查看项目说明 | 无外部服务时仍能进入样例 |
| 工作台 | 活动列表、最近任务、流程说明 | 新建活动、打开样例 | 首次空白、有历史、载入失败 |
| 品牌资料 | 产品事实、来源原文、语气和禁用词 | 新增、编辑、确认版本 | 未确认事实、冲突、保存失败 |
| 活动需求 | 分组表单、预算和日期、完成提示 | 保存、生成方案 | 字段错误、重复点击、生成中 |
| 活动详情 | brief 摘要、方案、角度选择、步骤进度 | 重试本步骤、生成内容 | 部分成功、输入已变更、接口失败 |
| 内容编辑 | A/B 标签、编辑器、引用侧栏、审核栏 | 编辑、送审、通过、退回、导出 | 脏数据、旧版本、阻断项、导出失败 |
| 数据复盘 | CSV 预览、错误清单、指标卡、内容对照 | 确认导入、查看公式、生成复盘 | 空数据、重复批次、口径不一致 |
| 运行记录 | 耗时、调用状态、模型、输入版本 | 查看本次错误、显式重试 | 超时未知、限额、模型拒绝 |

不显示假的百分比进度。生成中使用明确步骤，例如“正在生成小红书内容”；真实耗时不可预测时使用计时和可理解说明。

输入改变后提示“结果基于较早资料”，旧结果保留供比较，不能默默当作最新内容。危险动作如重置演示提供本地确认；演示重置只影响当前浏览器样例状态。

## 8 如何评价作品是否成功

### 8.1 软件完成目标

目标是面试官能独立完成一条路径。验收时由未参与开发的人按说明操作，记录卡点，而不由开发者代操作证明“可用”。

1. 公开样例无密钥可访问，3 分钟能理解核心价值，10 分钟能完成主要操作。
2. P0 功能可完成，关键异常有恢复路径，不出现数据丢失或跨用户泄露。
3. 固定黄金数据的所有计算正确，缺失值和零分母不伪装为零表现。
4. 每个导出内容可追溯到版本、审核状态和事实来源。
5. 真实模式至少完成一次全流程验收；若尚无可用凭据，明确记为未验收，不将样例结果充当真实调用。

### 8.2 AI 质量目标

建立 20 条常规需求，每条生成 2 次，再加 10 条异常需求。人工评价事实与来源、目标与约束、渠道适配、执行可行性、复盘可靠性，每维 1–5 分。常规结果平均分目标不低于 4，单维平均分不低于 3.5，且不允许有未解决的严重事实错误。

这里每份输出指一个完整工作流包：方案、小红书 A/B 文案、抖音 A/B 脚本和固定数据复盘。每包约四次模型调用，40 包至少 160 次调用，重试另计。12 个开发样例的方案及双渠道两轮生成和初评安排在 S4，复盘部分在 S6 接通后补齐；8 个保留样例的完整两轮安排在 S7。评测使用显式配置的受保护账号和独立预算，日上限可设为 40 次实际供应商调用；不能临时绕过生产权限或费用记录。

这些是固定样本下的发布门槛，不代表模型在任意输入下的总体准确率。格式合法、引用 ID 存在，都不能替代内容事实核对。详细规则见验收文档。

### 8.3 业务效率目标

待验证假设：对同一复杂度任务，工作台降低资料整理、重复提示、排版和数据汇总时间。先记录人工基线，再记录辅助流程，使用相同质量标准；若质量下降，不把更快视为有效提效。

记录从读 brief 到可审核内容、到导出、到复盘的主动操作时间和总等待时间，保留修改次数与错误数量。至少 5 组同类任务；条件允许时邀请第二名评审。报告中展示原始样本、中位数和范围。

没有真实投放实验时，不能声称转化率提升、获客成本降低或营收增长。模拟 CSV 只证明计算和复盘流程可运行。

## 9 从 0 到 1 的阶段安排

每个阶段结束须留存产物并通过阶段门槛。完整任务和依赖见 TASKS.md。

| 阶段 | 基础工时 | 要做什么 | 阶段产物 | 通过条件 |
| --- | --- | --- | --- | --- |
| S0 明确范围 | 8h | 确定案例、用户流程、数据与验收口径 | 产品基线、页面草图、样例数据定义 | 能完整讲清输入、输出和人工边界 |
| S1 工程骨架 | 6h | 初始化应用、样例模式、规范和 CI | 可启动的导航与演示入口 | 新环境按说明能运行基础页面 |
| S2 数据与权限 | 10h | 建表、迁移、账号、RLS、种子数据 | 真实数据存取和隔离测试 | 甲用户不能读取或修改乙用户记录 |
| S3 资料与流程 | 10h | 品牌资料、brief、输入版本、页面状态 | 不依赖模型的业务骨架 | 填写、保存、刷新、修改和版本检查成立 |
| S4 AI 生成 | 18h | 提示词、结构化方案、渠道内容、成本与失败 | 真实生成链路和可追踪记录 | 正常、拒绝、超时、重复请求均可处理 |
| S5 审核导出 | 8h | 规则、状态变更、审核、版本导出 | 完整内容交付流程 | 未审核不能正式导出，改稿使旧审批失效 |
| S6 数据与复盘 | 12h | CSV、指标、复盘、下轮 brief | 可复算的业务回传流程 | 黄金数据、幂等导入、复盘引用通过 |
| S7 综合验收 | 22h | E2E、人工评测、权限、可用性和性能 | 测试及评分报告、已修复问题 | 发布硬门槛全部满足 |
| S8 发布包装 | 6h | 部署、README、截图、录屏、演练 | GitHub、demo、视频与发布记录 | 新设备可访问，第三人可按文档复现 |
| 缓冲 | 0–25h | 处理部署、模型质量和联调的不确定性 | 变更记录 | 缓冲不用于新增无关功能 |

关键依赖：S0 → S1 → S2 → S3 → S4 → S5；S6 的纯指标函数和 CSV 样例可在 S3 后提前准备，完整复盘依赖 S4；S7 → S8。测试随阶段添加，S7 是汇总验收，不是第一次测试。

### 9.1 工期压缩策略

如果后续出现约一周的硬截止，先交付可披露范围的演示版：一个渠道、一套内容、事实约束、审核导出、固定 CSV 和基础复盘。先保住一条完成路径，裁剪第二渠道、复杂图表、内容日历和美化。公开样例和真实调用必须仍然分清。

不能裁剪的项目：密钥保护、数据权限、指标正确、模拟标识、审批版本一致性、核心故障提示。精简版只能称为精简 MVP，不能勾选原完整版所有任务。

### 9.2 进入开发后的协作方式

AI 辅助完成脚手架、代码、样例、测试、文档和排查；项目负责人负责理解需求、判断营销表达和解释取舍。每完成一个任务，记录变更文件、验证命令、结果和截图；完成一个阶段后演示该阶段可见行为。

后续用户授权实施时，直接从 T001 开始。真实模型凭据、部署账号及 GitHub 写权限若已具备则复用；尚不具备时先完成独立工作，把账号依赖明确记录为外部阻塞，不在代码或文档中伪造链接、密钥和测试结论。

## 10 成本和资源安排

所需资源：本地开发环境、GitHub、Web 托管、Postgres/Supabase 账号、一个真实模型 API 凭据。模拟模式不依赖模型和数据库账号即可启动。

规划预算建议：为开发期模型试验预留人民币 100–300 元，为托管预留每月 0–200 元。上述为个人预算上限建议，不是供应商报价；是否需要付费计划取决于部署时的条款、地区和额度。购买或开通付费服务前核对实际价格。

每次调用记录输入/输出 token、耗时、重试数和估算成本，价格表带生效日期。金额按供应商原币记录，若展示人民币必须使用显式汇率和日期。每日真实调用次数默认上限 20、单活动同时运行步骤上限 1；可在真实测试后调整。

建议给应用设置人民币等值 10 元/日的软预算预警和可配置的阻断额度。预算检查须对并发请求预留额度，未知计费的超时请求不能立即释放全部预留。应用账本是估计值，最终以供应商账单为准。

## 11 风险与应对

| 风险 | 提前识别 | 应对和验证 |
| --- | --- | --- |
| 功能越做越多 | 新任务不对应 F01–F10 | 记入 P1/P2，核心门槛通过后再考虑 |
| AI 生成空泛 | 评分低、人工重写量高 | 缩小任务、改善事实和示例，跑固定评测 |
| 事实幻觉 | 不存在的规格、库存、销量或背书 | 来源约束、规则检测、人工审核，不宣称自动完全解决 |
| 模型或网络故障 | 超时、拒绝、额度不足 | 保留输入和已完成步骤，明确失败，样例入口可继续 |
| 费用被滥用 | 未登录可调用、重复点击多次扣费 | 服务端鉴权、限流、数据库幂等和预算预留 |
| CSV 误导分析 | 缺失值、重复批次、口径不一致 | 固定模板、预览、校验、事务提交和来源记录 |
| 审核与导出不同步 | 审核后改稿仍可导出 | 通过内容版本与哈希绑定审核 |
| 部署在目标网络打不开 | 自己可访问，评审设备不可访问 | 使用目标网络抽查，提前准备本地与录屏备用 |
| 面试无法解释实现 | 只能背技术名称 | 按真实贡献演练，并走读一条 API 和一个测试 |

## 12 规划验收与软件验收的区别

本次规划验收：产品是否明确、主流程是否闭合、范围是否可控、任务是否有依赖与验收、技术设计是否支持功能、展示证据是否诚实。以上可以通过阅读本文件及关联文档完成。

后续软件验收：实际运行系统、执行测试、核对模型输出、检查部署和重现步骤。只有取得真实结果后才能标记完成。不能因为规划写了某项能力，就把它列为已实现功能。
